## stage 2 slack app
allow: slack/manifest.json lib/adapter.py lib/ingest.py bin/app bin/crawl tests/test_adapter.py tests/test_ingest.py fixtures/
spec: slack/manifest.json is the Slack app manifest: Socket Mode on, bot scopes chat:write, channels:history, channels:read, files:read, files:write, users:read, event subscriptions message.channels and app_mention, interactivity on. bin/app is a slack_bolt Socket Mode app: it subscribes to the refunds channel, turns each inbound message into a RefundRequest, and posts a Block Kit card with Approve and Deny buttons; button clicks are received by the same app. Env: SLACK_BOT_TOKEN, SLACK_APP_TOKEN, REFUNDS_CHANNEL. lib/ingest.py normalizes three sources to RefundRequest: slack(event) from a Slack message event, email(raw_rfc822) from an email forwarded into the channel as a file, zoom(transcript_json) from a Zoom recording.completed transcript posted into the channel. Every source ends up as a Slack message in the refunds channel, so there is one inbound path. bin/crawl is the forwarder: with its own access it pulls new refund emails from the inbox over IMAP and new call transcripts from the Zoom transcript directory, posts each into the refunds channel as a file, and records every posted item in log/crawl_seen.jsonl so nothing is posted twice; nobody forwards anything by hand. Env: SLACK_BOT_TOKEN, REFUNDS_CHANNEL, GMAIL_USER, GMAIL_APP_PASSWORD, GMAIL_QUERY, ZOOM_TRANSCRIPT_DIR, CRAWL_INTERVAL_S. Network only in bin/. lib/adapter.py: class Adapter(transport), transport has read_events() and post(payload); every call appends {ts, method, args_hash} to log/adapter.jsonl; under AGENT_READ_ONLY=1 post() sends nothing and returns {"status":"proposed_not_executed"}. Tests use RecordedTransport replaying fixtures/refund_001.json, fixtures/email_001.eml, fixtures/zoom_001.json. slack_bolt is imported only in bin/app, never in lib/.
exit: check green including slack_manifest; test_ingest asserts all three fixtures produce the same canonical RefundRequest fields; test_adapter runs with zero network and asserts the read-only branch

## stage 3 the agent
allow: lib/agent.py bin/agent tests/test_agent.py GOLDEN
spec: lib/agent.py decide(request, order, policy) -> Decision. Pure, no model call, no clock. Order of checks: escalate if amount_cents > order.amount_cents or amount_cents > policy.escalate_over_cents; else deny if hours_since_purchase > window_hours or status != "unused"; else refund. reasons is a list of the rule names that fired. Decision.hash = sha256 of canonical JSON of {request, order, window_hours, escalate_over_cents, action, amount_cents, reasons}; policy text and any timestamps excluded. bin/agent <fixture> prints the Decision JSON then a last line HASH <hash>; bin/agent --golden <fixture> writes the hash to GOLDEN. Why the channel matters: the refund is proposed in the Slack channel where support and the manager already work, and the decision is a receipt the manager can replay, not a chat answer.
exit: check green; test_agent asserts bin/agent on refund_001 equals GOLDEN; two clean checkouts agree on GOLDEN
